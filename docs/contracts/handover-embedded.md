## 3. 本期范围：7 动作 + 7 表情

本期只做站立、前进、后退、左转、右转、蹲下、趴下七个动作和 0..6 七张预设表情。动作码与需求 ID 的对应关系直接读 06:245-251 的「本期」列与说明列，本文件不重复列码。

其余编号保留但禁用：固件收到未启用码一律拒绝且不执行。摇尾巴、前跳后跳、伸懒腰、呼吸灯、语音、音乐、天气、自定义表情上传均不在本期，逐条处置见 [05 台账](../plan/05_需求追踪与验收台账.md) 第 1 节的「V3.1范围」与「本期处置」两列。

## 5. 共同验收的分界

- DONE 只证明固件步骤走完，不证明实际位移达标；姿态由 EB 实物验收另证（06:285）。
- 断链看门狗的处置先按 06:284-286 执行；机械承载测试若证明保持姿态会过热，须先改 06 再改固件。
- SIM 与主机解析测试可证明解析正确，不能替代 EA02 及之后的实物证据（04:13）。
- 状态布局只在完全相同布局下兼容；嵌入方若改布局，先改 06 并用固定向量选新协议版本，不接受后端按长度猜测。

## 7. 变更流程

任何帧、枚举、字段、时序的改动：先改 06（只在文件末尾追加新节，不插入已有章节中间，避免 `06:行号` 引用整体偏移）→ 再同步 `openapi.yaml` 与 `fixtures/` → 运行 `backend/tools/check_contracts.py`（在 backend 目录执行 `.\.venv\Scripts\python.exe tools\check_contracts.py`，或仓库根执行 `backend\.venv\Scripts\python.exe backend\tools\check_contracts.py`）→ 通知嵌入A/嵌入B/前端。不带 06 依据的实现改动不接受。
