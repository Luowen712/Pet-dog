## 协议对拍怎么做（现在就能做，不需要实物板）

双方各用自己代码生成下表 12 组帧，输出小写 hex 逐字节比对，SUM 必须**各自独立计算**，不许照抄文档里的值。

| 向量 id | 覆盖点 |
|---|---|
| `frames.action.request.stand.seq1` | 动作请求帧字段顺序与 SUM |
| `frames.action.accepted.seq1` | 受理确认 |
| `frames.action.done.stand.seq1` | 完成确认（站立） |
| `frames.action.done.walk.seq2` | 完成确认（前进，验证不同动作码） |
| `frames.action.rejected.busy.seq3` | 关联拒绝，设备忙 |
| `frames.action.rejected.unsupported.seq4` | 关联拒绝，不支持动作 |
| `frames.status.core9` | 核心状态上报全字段 |
| `frames.status.poll` | 催状态，无 seq |
| `frames.heartbeat.request` | 心跳请求 |
| `frames.heartbeat.ack` | 心跳单次回复 |
| `frames.face.set.happy` | 表情指令，无确认码 |
| `frames-bounds` | 长度、校验和、超长边界 |

后端侧已可复现（122 条测试全绿，`check_contracts.py` 0 ERROR / 0 WARN）。嵌入方交回时请附：生成脚本或单测、运行环境（编译器版本）、输出的 hex 清单。**"能收到"不算证据，要对得上字段。**

## 变更流程

任何帧、枚举、字段、时序的改动：先改 `06`（只在文件末尾追加新节，不插入已有章节中间，避免 `06:行号` 引用整体偏移）→ 再同步 `openapi.yaml` 与 `fixtures/` → 运行契约自检 → 通知嵌入A/嵌入B/前端。不带 06 依据的实现改动不接受。

```bash
# 在 backend 目录执行
.venv\Scripts\python.exe tools\check_contracts.py
```
