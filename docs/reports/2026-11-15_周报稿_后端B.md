2. POST /api/auth/logout：JWT 载荷加入 token_version(tv)，登出即自增 tv，实现全端会话一次作废；deps 依赖改为每请求校验账号状态 + tv，不再只验签，旧票（无 tv 声明）按失效处理，不默认补 0。

## 二、口头汇报稿（约 3 分钟，照着念即可）

这周我负责的是后端 B 线的数据和权限，主要推了三块：数据清点、身份鉴权、设备归属。

先说数据清点，也就是 BB00 这张卡。之前大家默认数据库里"只有两行用户"，我实际导出来是 4 行，清理掉临时账号后是 3 行，AUTO_INCREMENT 已经跑到 14，中间有 10 个 id 空洞。两台设备全部挂在 owner_id = 1 上，另外两个账号名下没有任何设备。这个结果说明原来的假设是不成立的，迁移的时候不能按"只有两行"来写脚本。

同时我把隔离测试库建起来了。测试会在 conftest 里、在 import 任何 app 模块之前就把 DB_URL 改到 pet_dog_test_bb00，并且断言库名里必须含 test，跑完前后正式库各表行数一条不差。这一条是 G0 门禁里最硬的证据。

还有个意外的发现：现有接口对查不到的电池电压是回填 0 的，前端一渲染就是 0% 电量和 0.00V，看着像真读数。我改成返回 null 了，前端能区分"没数据"和"真的是 0"。类似的契约偏差一共查出 6 处，都写进证据包交给 BB01 了。

第二块是身份鉴权。注册、登出、改密、注销四条接口全部落地。关键是登出和改密：JWT 里加了 token_version，登出就自增，所有端上的旧票当场作废；deps 也从"只验签"改成"每请求查账号状态 + 版本号"，历史上那些没有版本号声明的旧票一律按失效处理，不给它默认补 0，补 0 等于让以前所有旧票继续有效。

注销做成了两阶段：先 active → revoking，revoking 期间立刻拒绝一切访问，同时把用户名释放出来，然后是 revoked。清理任务可以崩了重跑，失败也不会把权限恢复回来。

第三块是设备归属。我把归属校验抽成了一个 get_owned_device，列表、详情、改名、状态、音乐五条路由全部走它，跨账号访问统一回 40400。在线状态按 9 秒静默判离线，走 heartbeat 上报，开发期的假心跳用开关关掉了，免得混进生产。

这周一共提交 11 次，新增 1686 行。BB00 已经完成，BB02 主体完成，BB03 和 BB05 各完成一半左右。

下周主要补三件事：一是 BB01 那几条数据库约束，owner_id 现在可空又没外键，msg_id 也不是唯一索引，数据库层挡不住脏数据，组长已经把 alembic 基线推上来了，我接着写 0002；二是 BB03 的配对码和 claim 事务，现在设备还是要靠 seed 写死 owner；三是 BB02 剩下的管理员 CLI 和限流。
