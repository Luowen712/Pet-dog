# 跨组接口与状态规则

版本：3.1｜日期：2026-11-10｜维护：后端A；复核：后端B、前端、嵌入A。

本文是本期跨组开发的唯一规则入口。其他计划只引用，不另定义枚举或字段。旧contracts已归档；任务J00把本文转成机器可读OpenAPI及固定测试向量，是实现与验证任务，不是让各组重新选择一套协议。实现遇到矛盾先记录决策再同步本文与样例。

## 1. 保留与必须改的边界

保留：Vue页面/组件/样式、Axios request入口、Pinia stores、DeviceSocket类、API路径/api、snake_case、统一信封、六态类型、ticket取票与HTTP对账、SQLAlchemy Base和现有表名、msg_id字段。

必须改：新增user.id；所有设备入口查owner；cmd_id由前端UUID幂等键决定；发送请求显式device_id；ACK不当完成；设备未知值用null；收到新状态后旧HTTP不能覆盖；当前设备可为空；不再把seq作为前端主键。

核心仅七个动作码48～54（十六进制0x30～0x36），其余21码表保留名称但禁用。不为了迁就旧组件的19按钮验收而声称全部已实现。

## 2. HTTP信封与核心字段

成功：HTTP200，{code:0,message:"ok",data:…,timestamp:毫秒整数}。
业务错误保留现有HTTP200+40000（结构/参数缺失）、40002（值非法）、40400（不存在或不属于我）、40900（冲突）。
身份无效HTTP401+40101；无管理员能力HTTP403+40300；限流HTTP429+42900；内部失败HTTP500+50000。与V3相比保留现有参数验证200通道，减少无收益返工。
错误可加reason/retry_after；前端不得解析中文message做分支。响应错误data=null，不在HTTP错误中同时返回“其实已执行”。

限流工程基线（单进程内存计数器，重启清空窗口；多 worker 必须改共享存储或在启动时拒绝启动）：

| 对象 | 键 | 阈值 | 超限 |
|---|---|---|---|
| 登录失败 | 账号 | 5 次/15 分钟 | 429+42900，带 retry_after |
| 登录失败 | 来源 IP | 30 次/15 分钟 | 同上；成功登录不清 IP 桶 |
| 注册 | 来源 IP | 5 次/小时 | 同上 |
| 配对码校验失败 | 设备 | 5 次/10 分钟，第 5 次后锁 10 分钟 | 锁定期内正确码也拒 |
| WS ticket 取票 | 用户 | 30 次/分钟 | 任一超限即拒 |
| WS ticket 取票 | 设备 | 60 次/分钟 | 同上 |
| 设备命令 | 每用户每设备 | 20 次/分钟 | 拒绝且不占幂等 key |

计数只累计失败与拒绝事件，成功登录不重置来源 IP 桶；以上为工程初值，G0 记录采纳后生效。

| 对象 | 字段 |
|---|---|
| User | id:number, username:string, name:string, role:"admin"或"user" |
| Device | 保留id/name/online/firmware/last_heartbeat/battery/location；battery和last_heartbeat可null；增加binding_state、control_state、supported_actions:number[] |
| DeviceStatus | 保留device_id/battery/voltage/action/face/music_state/track/volume/weather_code/temp/updated_at；未知业务字段null；增加online/control_state/session_id/state_revision |
| CommandReceipt | cmd_id UUID, device_id数字主键, action, seq可null, status, transport可null, reason可null, error_code可null, revision整数, created_at/updated_at为UTC时间字符串，finished_at可null |
| Ticket | ticket, expires_in_sec=30 |

voltage保持前端原字段名，单位固定V；固件mV在后端除1000，不改页面为另一套voltageMv。temp单位°C。UI显示null为“—”，不可回填0。

跨域（现有缺陷，无人认领）：backend/app/main.py 现在的 allow_origins=["*"] 与 allow_credentials=True 同时开启，携带凭据的请求本浏览器直接拒绝。首版按同源部署（后端托管构建产物或同域反代），生产不开放任意来源；开发期如需跨端口，用配置里的显式白名单，不写死 ["*"]。所有权：配置项归 config 配置所有者（见 02 的 BA02/BB02 拆分），中间件装配归 BA02。

binding_state=claimable/bound/retired；control_state=unconfigured/offline/ready/busy/recovery_required/handover_required/faulted。只有本人拥有、online=true、control_state=ready且动作在supported_actions中才接受新运动。在线不代表可控制。
session_id为后端会话UUID，state_revision在同会话内递增。新会话只通过当前连接的HTTP基线确认；不能拿两个UUID排序。

存储列与 API 字段的唯一映射（不引入第三套名字）：

| 来源 | API 字段 | 取值 |
|---|---|---|
| device.status | binding_state | claimable / bound / retired |
| device.status + 运行时 | control_state | unconfigured（未完成首次净化）/ offline / ready / busy / recovery_required / handover_required / faulted |
| device.handover_state | 不单独下发 | ready / required；required 时 control_state 必须是 handover_required |

binding_state 只由 device.status 派生；control_state 由存储列与进程内会话共同决定，任一方要求保守态时取保守值。DTO 与缓存不得反写存储列，也不得让前端从 binding_state 推断可控制性。

幂等：UNIQUE(actor_user_id,msg_id)。规范请求指纹含device_pk、当前be、action、固定speed/repeat。每次先核身份和owner；同键同体返回原单，即使设备busy也不另发；同键异体40900/idempotency_conflict。随机key不代替原子busy检查：同设备预约运动槽、插入命令、入队规则必须协调，两个并发新key也只能接受一条。

没有创建命令的busy/offline/unsupported错误不占key；用户重新点击使用新key。网络中断无法知道POST是否落库时，保留原key，查询并以同key同体手动“确认提交结果”；禁止自动换key重发。

cmd_id 与 msg_id 是同一个值：cmd_id 是 API、WS、前端的唯一命令标识（前端 Idempotency-Key 生成的 UUID），数据库 command_log.msg_id 存同一个 UUID，读写 DTO 时 cmd_id == msg_id。不生成第二个标识，也不在响应里同时返回两个字段。frontend/src/api/command.ts 里“命令主键（后端生成）”的注释随实现一并改正。

## 4. 命令状态机

| status | 存储编号 | 触发 |
|---|---:|---|
| pending | 10 | 已落库，尚无设备受理 |
| accepted | 20 | 可靠匹配0x81 |
| done | 30 | 可靠匹配0x02 |
| rejected | 40 | 可靠匹配0x05 |
| unknown | 50 | 超时、写入不确定、恢复后不明 |
| superseded | 60 | 保留；首版不启用运动抢占 |
| legacy_unmapped | 99 | 仅历史归档识别 |

transport：null尚未尝试，ok=0全写，write_failed=1确定从未write，partial_write=2可能部分写。
合法：pending→accepted/done/rejected/unknown；accepted→done/rejected/unknown；unknown→done/rejected仅在同一可靠映射、可能已写、收到有效迟到证据时。
迟到证据若纠正partial_write，同事务更新transport=ok并留下原错误审计；确定未write的命令禁止提升为done。done/rejected后重复帧幂等，迟ACK不能回退accepted。所有修改revision递增。

运动槽：
- 全设备只一条pending/accepted运动；调用层busy，固件也拒绝忙时运动。
- 确定未写失败可释放槽；done/rejected可释放槽。
- unknown且可能写出则recovery_required，不能简单删除pending后发下一条。
- 可靠迟到DONE可解除此次不确定；会话重建/人工恢复另走第9节。
- 外部语音首版关闭，防止无法归因的本地运动抢占远程命令。

不需要消息中间件或全量领域事件系统。数据库commit成功后发布WS；发不出去由HTTP恢复。write成功但DB提交失败时禁止重发：设备会话faulted，保留最小本机结果日志（cmd_id/session/seq/帧摘要/时间，无秘密），启动先与已落库pending核对；日志写入也失败就拒绝新控制，不能把“无证据”当成功。

## 5. WS与前端合并规则

保留现有{event,data}入口，不强制改所有旧事件外壳。新增字段放data，兼容现有state/music/weather处理器。

| event | data与用途 |
|---|---|
| command | 完整CommandReceipt；唯一命令结果更新流 |
| state | 完整DeviceStatus；未知字段明确null |
| link | {device_id,online,control_state,reason,session_id,state_revision} |
| ping | {server_time}；30秒一次，前端仅刷新看门狗 |
| ack | 可保留兼容受理通知；新版store不据此转done、不清pending |
| music/weather | 扩展开启，不代表具体命令执行成功 |

前端发POST前把key加入pending；早到WS能认领。HTTP与WS只接受revision>=已存值的同一cmd_id记录；终态不被旧pending覆盖。HTTP网络错不直接置设备失败，显示提交结果待确认。

现有DeviceSocket重用：每次连接取新ticket；增加attemptId，旧取票/旧socket onclose/onmessage不能更改新连接。pet store继续generation机制但扩展到onEvent、toast、所有异步回调。request捕获发起时sessionEpoch，旧401不能退出新账号。

重连：先建WS，暂存最多128个当前连接事件→GET设备快照→确认session_id并按revision重放→GET仍待结果的cmd_id（最多20，超出分页处理或提示人工查询，不能刷新丢证据）。旧连接的缓存不重放到新连接；缓冲溢出重开同步。HTTP状态40400代表不可查询，不等于done。
用户刷新前可保存最多20条{user_id,device_id,cmd_id}，不存密码；重新登录只恢复相同user.id条目，解绑后删除可见缓存。

后端每WS队列128；新遥测只替换同设备未发遥测或删除遥测，不挤掉command/link；关键事件放不下关闭慢连接。关闭不是可靠消息送达保证，数据库才是结果依据。
ticket绑定uid/tv/device/be，30秒一次性；握手原子消费+查库授权。应用本地撤销同步清票据/队列/连接，发送任务每次发送前核对当前授权版本；已进入socket网络栈的数据无法追回，不承诺撤销后用户物理上看不到已发送消息。
关闭码是本表唯一登记处，前端按码分支，不解析关闭原因字符串：

| 码 | 触发 | 前端行为 |
|---|---|---|
| 1000 | 用户主动关闭、页面卸载 | 不重连 |
| 1001 | 服务端重启或进程内非预期异常 | 封顶退避重连（1→2→4→8→10 秒），每次连接重新取一次性 ticket |
| 1004 | 身份失效（换票后 tv 与已登录身份不一致、账号注销 revoking/revoked、改密、登出全部会话） | 校验回调所属连接代次仍为当前代次后，走统一登出：清 token 与用户、清设备选择、跳登录；不自动重连 |
| 1008 | 设备归属丢失（解绑、被他人认领、管理员回收该设备授权），身份仍有效 | 停止该设备的自动重连，刷新本人设备列表，保留登录态；若当前设备已不在列表，清空当前设备选择 |
| 4003 | ticket 无效/过期/已使用 | 重新取票后重连；取票返回 403/40400 时停止重连并重载设备 |
| 4009 | 同一 (uid, device_pk) 连接数已达上限 3 | 停止自动重试，展示“该设备已在其他窗口打开”与手动重试入口；重试创建新连接实例 |
| 1011 | 服务端内部错误、队列溢出 | 与身份失效分离：按同一或更宽的封顶退避重连，连续失败达阈值后给出可见提示，稳定恢复后清除 |

注销同事务内 tv+1 与解绑同时发生，连接按 1004 处理（身份失效优先于设备归属失效），不取决于哪个通知先遍历到该连接。4001 不再表示关闭原因：参数与格式错误由 HTTP 40000/40002 承接。普通断线按 1/2/4/8/10 秒退避并封顶 10 秒；75 秒无任何消息视为僵死连接强制重连。

连接槽的建立与释放（同一 (uid, device_pk) 至多 3 条）：

1. 握手成功后按连接 ID 登记槽；超限对**新连接**发 4009 拒绝，已建立连接不受影响。
2. 正常关闭、鉴权撤销、handler 非预期退出，一律在 finally 里按连接 ID 幂等删除该槽；不得只按 uid/device 删除，避免旧连接退出误删新连接占用的槽。
3. 半开连接由协议层 Ping/Pong 判定：Ping 间隔 20 秒、Pong 超时 10 秒（Uvicorn 已有 ws_ping_interval/ws_ping_timeout，按此配置，不自实现），最后一个成功 Pong 之后 30 秒内释放槽。
4. 槽表只在进程内，不落库；进程重启自然清空。
5. 前端 75 秒静默看门狗只是浏览器恢复手段，不作为服务端释放依据。

验收：造满 3 条 → 第 4 条收到 4009 → 分别测正常关闭与拔网线无 Close 帧两种断法 → 槽按上述时机释放 → 释放后主动重试成功。

## 7. SendGate与超时

所有用户发起设备write，包括动作和表情，都经过同一个SendGate；不能只保护0x01。自动心跳/快照由system会话上下文允许，但不得生成用户动作或在新be下记录旧数据。

锁序统一SendGate→admin命名锁（需要时）→user→device→claim。只读无须SendGate，claim也需同一顺序协调缓存换代。哈希计算先完成再拿锁。

命名锁的可执行定义（缺一条即视为未实现）：

1. 锁名是常量 `petdog:admin:v1`，不拼接库名、用户名或时间戳；总长固定不超过 64 字符。
2. 必须在固定的专用连接上获取（CLI 全生命周期同一条连接），不得从连接池临时取。
3. `SELECT GET_LOCK('petdog:admin:v1', <超时秒>)` 返回 1 才算取得；返回 0 是超时、返回 NULL 是错误（连接断开、参数非法、锁名非本地），两者都按失败关闭处理：显式 ROLLBACK、退出码 3、不再继续任何写操作，绝不当作“可能已取得”继续。
4. 同一连接重复 GET_LOCK 会累计计数，必须与 RELEASE_LOCK 严格配对；释放返回 1 才算释放成功，返回 0（不是持有者）或 NULL（连接已断）一律销毁该连接并报错，不复用可疑连接。
5. P0 只支持单写 mysqld；部署在只读副本或组复制多写时启动即拒绝，不静默降级。
6. 命名锁只保护跨进程的管理员计数与状态迁移；设备发送权的互斥仍由 SendGate 与主机排他进程锁负责，二者不可互相替代。
同步锁只在线程使用；write_timeout=200ms，队列32，排队超过1秒未开始write记unknown/write_failed/queue_expired；心跳合并至多一个，已到期心跳优先，不饿死固件看门狗。
DB会话锁等待初值2秒、操作整体5秒；超时/死锁显式rollback，不能持锁继续。实际配置、工具对取消的支持要测试；超时不等于线程结束，直到writer退出不释放其发送权。

在线撤销必须通过同一进程服务。CLI会改授权/设备状态的操作一律要求获取同一主机排他进程锁，拿不到提示先停后端，不绕开运行实例。命名锁保护跨进程管理员计数，不能替代设备进程锁。

600ms ACK预算从完整write确认后计；T_done从受理起算，为该动作板上最大测量时长+600ms。打招呼步骤求和1600ms不是本期七个动作的实测值。尚未测时的动作只可在开发SIM或人工监护联调模式用30秒硬上限，正式能力列表禁用；该模式不能替代G4正式能力验收。pending登记必须早于write，防极速回包；接收线程到帧立即捕获单调时间，超时裁决使用该时间，避免DB阻塞造成伪超时。

## 8. 帧与固件合同

AA 55 LEN CMD DATA SUM；LEN=DATA长度，0..31，总长LEN+5≤36；SUM=~(LEN+CMD+DATA总和)&255。不是CRC。连续帧物理停止位结束→下一起始位至少20ms；write返回不等于线路发送完，记录长度/baud保守预留并上逻辑分析仪验证。

| CMD | DATA字节 | 语义 |
|---|---|---|
| 01 | action,speed=0,repeat=1,seq | 动作请求 |
| 81 | 01,seq | 已接受动作 |
| 02 | action,seq | 动作完成 |
| 05 | error_code,seq | 关联拒绝 |
| 03 | 下表9字节 | 状态上报，每5秒或06触发 |
| 04 | 空 | 心跳请求；后端每3秒发送 |
| 84 | 空 | 收04后回一次；不因84再回复 |
| 06 | 空 | 催状态，无seq，不按请求配对 |
| 07 | face(0..6) | 设置预设表情，无确认码 |
| 08～0B | 保留旧编号 | 本期不开放，无0x87 |

03偏移：0电量0..100(255未知)，1动作(0空闲)，2表情0..6(255未知)，3音乐状态(255未知)，4曲目(255未知)，5～6电压mV大端(65535未知)，7天气(255未知)，8有符号温度(-128未知)。核心支持LEN=9，未做音乐天气填未知。兼容前缀仅同布局成立；LEN6不足两字节电压时电压null。动作字段是设备上报，不能POST后乐观改成目标动作。
表情ID明确0..6，前端显示序号1..7不改变线上编号。当前工程如果不一致，J00统一转换。
固件错误新增精确定义：01=不支持动作，02=参数非法，03=完整超长动作帧，04=设备忙。仅校验正确且可提取seq才回05。坏帧/无法关联错误只计数，不随意取垃圾seq回包。
帧向量：请求站立seq1 = AA 55 04 01 31 00 01 01 C7；受理 = AA 55 02 81 01 01 7A；完成 = AA 55 02 02 31 01 C9；心跳 = AA 55 00 04 FB；确认 = AA 55 00 84 7B。J00工具独立计算每个SUM，不能靠文案假定正确。

核心固件非阻塞tick，UART中断入环形缓冲；7动作占同一资源，忙时拒绝新运动；相同seq+相同payload重复请求不重复执行，只重发已有结果；相同seq异payload拒绝。去重缓存至少覆盖本会话255个seq，可存定长动作/参数/状态小表；启动清空，所以主机必须重建会话。
动作DONE表示固件步骤走完，没有编码器不能证明实际位移完全达标；物理姿态由HW验收另证。
9秒无有效04停止启动新动作步骤、保持PWM当前姿态；中断中的动作不发虚假DONE，主机转恢复状态。该策略依机械承载测试，若保持会过热需EB/EA改安全姿态合同后再发布。

## 9. 设备会话、序号和交接

首版明确保守限制：1..255同会话不复用。不是“等30秒就安全”；没有线上epoch不能证明任意迟到帧不串。显示剩余会话容量，耗尽返回40900/seq_exhausted，无自动发新动作。
序号分配先记会话记录再write；进程重启绝不假定上次没发。每次复位/链路重建新session_id，旧未终结改unknown，不自动重发。

三种恢复：
1. 同主人的瞬时WS断线：只HTTP对账，不动硬件会话。
2. 同主人的串口重建/255耗尽/未知执行：停止后端，物理复位与蓝牙缓冲清理，CLI recover-device；保留owner/be，旧命令保持结果未知或已有终态；新会话不能认领旧seq。
3. 解绑转移主人：事务立即owner空/be+1/handover required，清旧缓存；停止后端并净化设备后CLI complete-handover；此时才ready可发新配对码认领。

recover-device和complete-handover均需主机锁+expected_be+expected_session CAS+设备登记标识人工确认+proof_id。设备注册初始required；先完成首次人工净化再签码，避免“先登录才能净化、先净化才能登录”的循环。CLI不需要网页token，使用受保护本机DB身份。
程序下次真实串口启动：必须有与expected_be/expected_session匹配的明确准备标记，原clean_shutdown本身不替代净化。启动事务一次性消费准备标记并登记新session，未满足就recovery_required；已准备只做连接和新快照，快照通过才ready。进程意外崩溃使下一次必须人工确认。SIM可在重置全部模拟缓存/延迟任务后自动准备，但不得把SIM恢复结果当成硬件证据。净化证据针对蓝牙桥实际缓冲，无法证明时改USB-TTL演示，不假称自动安全。

解绑提交前已经写出的动作可能继续，不能把解绑按钮叫急停。实体电源开关由EB提供；安全摆放先抬离桌边。
0x03没有be：未绑定/未净化时只诊断不持久化用户遥测；绑定完成且新会话才接收新快照，缓存按(device,be,session)隔离。

## 10. 数据迁移最小闭环

保留现有user/device/command_log/telemetry/scene/face_asset表名和id；msg_id复用。新增列/表完整清单由BB01编制，至少：
user.status/tv/deleted_at；device.owner_id FK可空、be/bound_at/status/handover_state；command_log.device_pk/actor_user_id/be/tv/revision/transport/reason/session_id；telemetry.device_pk/be/session_id；device_claim、audit、legacy_row_archive、device_session_record。
不新增dispatch_generation列。运动槽在单进程内有锁、落库有命令，重启先恢复不重放。

首版停机迁移：清点→隔离恢复→0001基线→0002新增→0003回填归档→0004验证→0005约束→起新版本。真实schema不一致不得强stamp。
外键顺序：先父user/device→claim/audit→command/telemetry；历史无法证明owner的子行先归档hash核对再删除活跃源行；有其他子表引用时先迁/归档子表，禁止CASCADE默默删。Scene/FaceAsset不能因为暂不开页面就遗留错误owner；按同一策略回填/隔离。
演示账号禁用，真实用户按清点保留；每个改名/随机hash仅执行一次，重跑不再修改。audit保留数字身份，撤销账号不硬删除父行。
0004检查每张活跃表外键、NOT NULL目标、唯一key、归档hash和数据计数；通过才contract。actor_user_id与device_pk等历史归属无证据不能拿管理员ID补空。

归属约束必须落成可执行的 DDL 项，不能只写“归属等价”四个字：

| 约束 | 定义 | 目的 |
|---|---|---|
| device.owner_id 外键 | 可空，引用 user.id，删除父行时 RESTRICT | 允许未绑定设备存在 |
| uq_device_owner | UNIQUE(owner_id)，允许 NULL 重复 | 一个账号至多一台设备 |
| device_claim.device_pk 唯一 | UNIQUE(device_pk) | 每台设备至多一行配对码记录 |
| device.status 与 owner_id 一致 | CHECK：(owner_id IS NULL AND status<>'bound') OR (owner_id IS NOT NULL AND status='bound') | 有主必 bound，无主必非 bound |

以上四项在 0005 建约束前先由 0004 验数：任一现存行不满足即中止迁移并人工清点，不自动改写归属。验证只在真实 MySQL 上做，不用 SQLite 代替（见 01 的 G1）。
模拟三个DDL和三个DML确定failpoint，重跑不重复归档/改名；比较规范化业务字段摘要。备份恢复到空库再实跑两账号隔离。
