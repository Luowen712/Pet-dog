## 1. 先明确哪些成果保留

保留当前Vue/Vite/Pinia工程、全部页面和组件、配色布局、API模块、DeviceSocket类、票据和退避逻辑、getCommand对账、CommandStatus六态类型。**不重新建项目、不重画界面、不因扩展延期删除页面源码。**

已读代码中必须修的点：
- pet.onAck目前把OK直接变绿并删除pending；这是受理与完成混淆。
- sendAction等HTTP返回后才登记cmd_id，早到WS无法认领。
- DISPLAY_TIMEOUT_MS把未完成动作标fail；SEQ_RETIRE_MS删除仍需对账记录。
- connect的onEvent没有绑定generation，loadWeather/发送结果等旧请求也可能回填。
- device.currentId可默认1，列表为空不清当前设备；AppLayout仍无设备就pet.connect。
- User缺id，localStorage未按user.id隔离，旧401可能清新登录。
- face POST和rename已有调用但后端未实现，按06补齐，不另外改接口方法。
- 六态已经有了，不需要引入第二套全局状态管理库。

规则看[06共享规则](06_跨组接口与状态规则.md)，任务验收写[05台账](05_需求追踪与验收台账.md)。

**前置：** W2可先完成基线、请求选项和独立的sessionEpoch实现；开始按user.id隔离状态及验证真实身份响应前，须收到BB02提供的User.id/身份样例（不必等待BB02整卡完成）。

**文件：** utils/session.ts/request.ts/errors.ts、stores/auth.ts/device.ts；新增 api/setup.ts（FE02 使用，接口与请求选项由本卡提供）

**按顺序做：**
1. token/user保留既有保存入口，device选择按user.id分区；旧mock明文键做一次性清理，迁移不删不相关浏览器数据。
2. 引入sessionEpoch，登录切换/退出先增加，再清设备、pet、WS；跨标签页storage或BroadcastChannel只同步失效，不广播密码。
3. request发起捕获epoch；成功、失败、toast、401 redirect全部先核epoch；允许登录匿名请求但不复用上一用户授权。RequestOptions 在现有 silent 之外增加两项：anonymous/skipAuth（不带 Authorization）与 suppressSessionInvalidation（401 只作为调用方错误返回，不清会话、不跳登录）。现有 handleUnauthorized 是 request.ts 内部未导出的函数，需抽成可复用的唯一入口，供 1004 与 HTTP 401 共用，不在 ws 层另写一套登出。
4. 解析HTTP403/429/500的统一信封，429按retry_after；参数业务错误仍走现有ApiError。
5. device.load合并并发；空数组设currentId=null；select验证属于列表；旧账号请求不得覆盖新账号列表。
6. 清理本地设备键：session.ts 的 clearSession 只删 token 与 user，不删 petdog_device；getStoredDeviceId 在键缺失时回落 '1'。device store 需补 clear/reset，clearSession 一并删 petdog_device，读取时缺键返回 null 而不是 1，否则上一账号的设备会被下一个账号继承。旧 mock 明文键同样在此一次性清理。

**完成判据：** 延迟A的401，切换B后到达不清B；空列表不connect；改名/普通页面错误仍有正确message。

**交接：** W2先交请求选项、sessionEpoch方案及api/setup.ts调用签名，供FE02并行准备；收到BB02的User.id/身份样例后完成账号隔离与联调；整卡完成后交BB两账号fixture测试结果，FE02使用统一reset而不各页清一半。

### FE03 命令状态与WS恢复（16h；W3—W5）

**前置：** FE00/01，BA03/05样例与服务

**文件：** api/command.ts、utils/ws.ts、stores/pet.ts、ActionButton.vue；新增commands.spec.ts/ws.spec.ts

**按顺序做：**
1. sendAction先生成UUID并登记本地记录，sendCommand(deviceId,action,key)附幂等头；POST前锁定运动按钮，业务busy解除本地提交态。
2. 同cmd_id按revision更新，accepted继续等待、done才绿、unknown显示结果不明；旧ack只补受理显示，不清pending。
3. 删除3秒判fail和30秒丢待对账记录；可显示仍等待，网络失败保存key并查结果，不自动换key重发。
4. DeviceSocket增加attemptId；旧取票结果、旧socket close/message不能作用新连接；403/40400停止重连、429等待。
   关闭码按06§5的表分支，现在的 switch 只有 1000/4001/4003/4009/default 且语义是旧的：1000 不重连；1001 封顶退避重连并重取一次性 ticket；1004 身份失效走 FE01 的统一登出（回调查代次，旧连接不得清掉新登录）；1008 只停该设备重连、刷新本人设备列表、保留登录态，当前设备已不在列表则清空选择；4003 换票后重连，取票 403/40400 停止；4009 停止自动重试并给出手动重试入口；1011 与身份失效分离，封顶退避并在连续失败达阈值后给出可见提示。ws.ts:115 的"关闭码语义见 docs/contracts/events.md"注释已指向归档，改成指向06§5。
5. 把pet所有回调和异步请求都绑定generation，reset清电量/动作/表情/连接/待命令缓存，不能保留上一主人状态。onEvent 与 onFatal 现在都不带代次检查（只有 onStatus 有），必须统一补上；onFatal 目前只弹一条 toast，1004 必须走统一登出而不是弹窗。DeviceSocket 的回调签名需增加连接代次或关闭码，供上层按码分支。
6. 先订阅缓存事件，再HTTP基线并核session/revision，再查询待命令；刷新保留最多20个当前user的cmd_id，查询失败保留未知提示。
7. command事件早到HTTP后到、WS断开期间完成、旧HTTP快照迟到、同浏览器切账号分别写测试。
8. 界面action只由设备状态更新，不再发送成功就action=code；unknown+recovery_required禁新运动并显示恢复说明。
9. 抖动计数与可见提示：现有 scheduleReconnect 只有一个 retry，且 onopen 立刻清零，装不下"首次连续失败"与"稳定后反复掉线"两种情形。拆成两个计数：openFailures（从未连上即失败，open 清零）与 dropCount（连上后再断，仅在 open 持续 30 秒或收到有效服务端事件后清零），阈值 5 次或首次失败起 60 秒。达到阈值后在离线横幅里给出可见错误文案（AppLayout 现有 showOffline 只有提示没有动作），手动重试按钮调用 pet.connect 创建新实例。

**完成判据：** N01/N02/N09/N11/N21对应UI行为可复现；任一顺序不回退；ACK不再代表完成；无设备不取票；1000/1001/1004/1008/4003/4009/1011 七种关闭码各有一条用例，其中 1004 与 1008 分别断言"清身份跳登录"与"保留登录态只清设备"；同设备 4 条连接时第 4 条展示 4009 与重试入口。

**交接：** 给BA实时合并测试和慢连接截图，BB核对Receipt查询权限。

**失败出口：** 拿不到结果不显示done；40400为不可查询，不靠action+时间猜是哪条命令。
