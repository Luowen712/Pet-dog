# 嵌入式执行计划

版本3.1｜2026-11-10。嵌入A负责固件78h，嵌入B负责硬件60h。两人共同做板上验收，但不把采购和软件互相推给对方。

## 1. 当前事实与边界

仓库firmware/hardware仍是占位，参考DOCX中的代码不等于已可编译工程。先收齐可编译的Keil工程、原理图和实物，保留原SDK结构；不要把HAL示例直接拼进标准外设库。
核心动作0x30～0x36共7码，表情0..6共7张；21码表只是保留编号。先站立/前进打通，随后补齐其他基础动作。语音/音乐/灯光/跳跃没有通过扩展门禁前不接入主控制流程。
协议看[06](06_跨组接口与状态规则.md)，实测进[05](05_需求追踪与验收台账.md)，不在本文件另定字节表。

## 2. 嵌入A 固件任务（78h）

EA00→EA01→EA02→EA03→EA04→EA05→EA06。缺板时EA01可做主机解析测试，但EA02及之后机械行为不能标HW通过。
### EA00 工程入库和最小编译（6h；W2）

**前置：** 原工程与下载器来源，EB00实物清单

**文件：** firmware/原Keil工程、firmware/README.md

**按顺序做：**
1. 取得全部.c/.h/启动文件/链接配置/工程文件，记录来源和许可证；不只上传hex。
2. 干净路径编译，记录编译器/SDK和警告；找出main/UART/PWM/OLED驱动位置。
3. 使用EB核对的引脚，先亮屏或LED验证下载；舵机未校准前不加载复杂动作。
4. 给BA实际接收缓冲、串口波特率和调试输出分离方式。

**完成判据：** G0固件编译证据登记于05；别人按README可编译，工程不依赖个人绝对路径；最小烧录可复现。

**交接：** 交EB烧写/接线条件，BA获得协议接入位置。

**失败出口：** 缺工程或SDK先登记阻塞，不能把文档抄代码标成工程完成。

### EA01 UART帧和固定向量（10h；W2—W3）

**前置：** EA00、BA01/J00向量

**文件：** firmware协议模块、主循环与UART ISR

**按顺序做：**
1. USART3 9600 8N1，ISR只入环形缓冲，主循环单消费者；记录溢出计数。
2. 实现LEN=DATA、SUM、空载、0..31、半帧超时、粘包、噪声恢复；超长有界丢弃不越界。
3. 独立发送队列落实20ms物理帧间隔；ACK/DONE不可被遥测淹没，遥测只保留最新待发。
4. 仅完整校验有效且可关联seq的动作错误回05；不回垃圾seq。
5. 运行请求/ACK/DONE/04/84固定向量，与后端同一输入逐字节比较。

**完成判据：** G1固定帧向量证据登记于05；10组有效/无效/分段向量输出确定；无死循环和缓冲越界；逻辑分析仪间隔符合。

**交接：** 给BA原始hex，不用“能收到”代替字段证据。

**失败出口：** 解析不过先不接真实动作，避免错误帧触发运动。

### EA02 七基础动作tick（20h；W3—W4）

**前置：** EA01，EB01/02供电和行程校准

**文件：** firmware动作状态机、动作表、能力表

**按顺序做：**
1. 每个动作写步骤表、目标角度与hold时间，主循环tick推进；没有长Delay阻塞协议。
2. 先站立/前进与后端闭环，再蹲下/趴下/后退/左转/右转；显式switch或稀疏表。
3. 接收时检查action/speed/repeat，busy拒新运动；合法后保存seq再回81，最后一步结束回02一次。
4. 实现同会话seq去重，相同请求不重复运动，相同seq异payload拒绝；上电清表配合主机会话恢复。
5. 未实现动作回不支持，supported_actions只公布实际验证通过码；所有位置由机械校准约束。

**完成判据：** 七动作逐个实物通过；动作期间串口仍能回心跳/状态；重复seq不重复执行，busy请求不抢占。

**交接：** 给BA动作上限初测、FE能力列表，EB观察电流和机械干涉。

**失败出口：** 动作堵转/过流立即断电，先修机械/轨迹；不能延长超时掩盖物理问题。

### EA03 心跳、状态和恢复（10h；W4）

**前置：** EA02、06状态布局

**文件：** firmware watchdog/telemetry模块

**按顺序做：**
1. 每5秒发03，06催发合并快照；动作空闲0，未实现音乐天气字段填约定未知。
2. 收到04回空84一次，84不回显；9秒无有效04停止启动新步骤并保持姿态，记录恢复状态。
3. 当前动作被看门狗中断不发DONE；后端应进入unknown/recovery_required。
4. 设备复位后清动作状态和去重缓存；与BA/EB演练清蓝牙缓冲和重新连接，收新快照。
5. 如果上行状态布局不同，不接受后端按长度猜测；通过固定向量选择统一协议版本。

**完成判据：** 单独断下行仍能上报但动作不再推进；断上行后端9秒离线；无04/84回显风暴；LEN6主机不会读半电压。

**交接：** 交BA恢复状态证据、EB看门狗保持姿态的机械测试。

**失败出口：** 保持姿态不安全需共同修改安全行为并重测，不擅自改成回中位。

### EA04 七表情与联动（10h；W4—W5）

**前置：** EA02、OLED驱动、FE表情编号

**文件：** firmware显示模块、七预设数组

**按顺序做：**
1. EB确认安全摆放后上电，3秒内显示自检页并记录启动行为；固定128×32七张图，0..6编号；下半未做天气可留静态，不显示虚假值。
2. 07选择预设，不发不存在0x87；03上报当前face给前端观察。
3. 七动作开始选择约定表情，结束回默认；给FE一张动作→表情映射表。
4. 缓冲按页刷新，不用整屏长阻塞影响串口；连续20次切换观测闪烁和丢帧。

**完成判据：** 安全摆放上电3秒内显示自检页；点七张实物一致，动作联动正确，串口不中断，图案占用和刷新耗时有记录。

**交接：** 交FE00/04位图缩略预览与0..6对应表。

**失败出口：** 自定义上传不在本期，不实现未经定义的分包命令。

### EA05 测时、故障和固件回归（16h；W5—W6）

**前置：** EA03/04、EB供电范围

**文件：** 动作测时表、固件测试日志、tools生成输入

**按顺序做：**
1. 每基础动作在标称及最低允许电压各20次，记录ACK到DONE最大值、tick延迟、异常；不是取平均。
2. 步骤hold求和仅作理论输入，真机最大值写机器块，由BA生成后端上限。
3. 100次顺序测ACK延迟；新会话200条顺序运动统计；额外并发busy/重复帧/坏SUM组分开。
4. 与EB连续2小时测试，记录复位原因、队列/环形缓冲溢出、心跳停步、供电。
5. 对失败动作修复后只重复受影响组，再整机回归一次，禁止删失败记录。

**完成判据：** G3提交测时进度，G4前补齐正式能力测时；G4无复位死机/串号重复，正常组受理与完成≥95%；所有失败有分类。

**交接：** 交BA计时常量、BB发布固件版本、FE演示证据。

**失败出口：** 时长或供电无法达标就保持该动作未通过，报告范围风险。

### EA06 冻结与烧写交付（6h；W7—W8）

**前置：** EA05、EB装配完成

**文件：** firmware README、工程/hex交付包

**按顺序做：**
1. 清目录独立编译，记录源码commit、编译器、hex hash和协议版本。
2. 写下载器接线、BOOT配置、串口占用与恢复步骤，标清烧录和运行通信不同。
3. 三次演示前按同样顺序上电/净化/登录，不用临时固件混入。
4. 保存已验证回退固件和对应配置，不现场加新动作。

**完成判据：** 陌生组员可烧录并运行七动作/七表情；发布包与录屏一致。

**交接：** 组长与EB签收，BA记录协议兼容版本。

**失败出口：** 任何现场修复重新编译标版本并复测，不复用旧测试结论。

## 3. 嵌入B 硬件任务（60h）

EB00→EB01→EB02→EB03→EB04→EB05。PCB是可回退载体，不挤占安全测试。

### EB00 实物和采购清点（6h；W2，11/12前提交）

**前置：** 可访问实物/采购信息

**文件：** hardware/BOM、inventory、接线初稿

**按顺序做：**
1. 清点主控/下载器/USB-TTL/舵机/OLED/电源/蓝牙，写型号、数量、到货日期与缺件替代。
2. 确认USART1语音、USART3通信、PA2/PA3舵机占用；拍清模块丝印。
3. 11/15前至少开发板+下载器+USB-TTL+单舵机可测；缺件立即借用或明确日期。
4. 预算按真实报价记录，不沿用旧报告价格当采购事实。

**完成判据：** G0实物到位报告证据登记于05；所有关键件有实物或明确供给日期，组长能判断G2风险。

**交接：** EA00编译目标和下载器，BA串口设备能力。

**失败出口：** 缺板标硬件阻塞，不等待到联调周才报告。

### EB01 接线与安全供电（12h；W2—W3）

**前置：** EB00、EA最小固件

**文件：** hardware/wiring、电源测量记录

**按顺序做：**
1. 确认USB-TTL逻辑电平、TX/RX交叉、共地；USB-TTL接USART3时断开蓝牙模块驱动。
2. 舵机独立供电轨和逻辑共地；核对电池/稳压/线材额定能力，提供实体断电开关。
3. 先空载再单舵机，测电压跌落和电流；下载器/USB供电不会与外部电源反灌。
4. 记录允许电压范围、过流/温升停止条件，EA用这些值限制动作；不能直接把旧文档3A当所有配置安全值。

**完成判据：** 接线图与实物一致，单舵机负载不复位；危险接法已排除并有测量记录。

**交接：** EA02校准可用电源；BA串口抓帧环境。

**失败出口：** 电源不稳先停止多舵机测试，不能靠软件反复重连掩盖。

### EB02 机械校准与装配（12h；W3—W4）

**前置：** EB01，EA02单动作

**文件：** hardware/calibration、assembly

**按顺序做：**
1. 逐个舵机卸载校准方向/中位/行程，记录左后等反向映射。
2. 装腿后从保守角度逐步增加，检查齿轮/外壳/地面干涉，不统一硬写90°。
3. 与EA测站立、前进、趴蹲、后退/转向；准备桌边安全区域，不宣传无传感器防跌落。
4. 固定线束与接头，检查运动不会扯断UART或电源。

**完成判据：** 七动作机械可执行，重复后无累积错位/堵转/接线松动。

**交接：** EA步骤参数和限位；组长实物视频。

**失败出口：** 机械问题先修装配，禁止只改动作时长掩盖卡死。

### EB03 蓝牙与设备交接实测（8h；W4—W5）

**前置：** EB01/02、BA04/EA03

**文件：** hardware/link-test、恢复操作表

**按顺序做：**
1. USB-TTL先验证协议；确认蓝牙实际模块对Windows暴露的串口能力，登记COM映射。
2. 断电/断开蓝牙后检查旧字节是否可能在重连后到达；配合BA旧seq注入。
3. 写净化步骤：停止后端→切断/复位板与桥→清串口本地缓冲→核设备登记→CLI恢复准备→启动读新快照。
4. 分别演练同owner recover和换owner handover；记录操作人、设备、be/session、proof_id，不只点网页解绑。

**完成判据：** 恢复步骤可重复，旧回执不归新主人；不支持净化的蓝牙走USB-TTL演示并标限制。

**交接：** BB04 CLI输入依据、BA会话安全边界、FE恢复文案。

**失败出口：** 物理映射不确定不开放控制，不用数据库owner推断当前接的是哪块板。

### EB04 PCB或替代载体与长跑（14h；W5—W6）

**前置：** 已验证引脚/供电/机械

**文件：** hardware/pcb与assembly、长跑记录

**按顺序做：**
1. 开发板验证后才冻结PCB引脚与电源；下单前EA复核，不为赶工先画后改。
2. PCB到货先短路/电源空载检查，再主控再单舵机，逐级加载。
3. 12/13未达标使用已验证开发板/洞洞板；不把未通电PCB算整机完成。
4. 与EA/BA做2小时长跑、200顺序动作与看门狗姿态保持，记录最低电压和复位迹象。
5. 备一套已验证线材/电源，音乐语音扩展未选不额外焊入影响核心。

**完成判据：** G4实物稳定，有实际采用载体/电源/固件记录。

**交接：** 组长决定PCB回退，EA/BA收到异常时刻对应日志。

**失败出口：** 长跑异常停止扩展，按供电→通信→协议→动作逐层定位。

### EB05 硬件交付与演示保障（8h；W7—W8）

**前置：** EB04、EA06

**文件：** BOM、照片、烧写接线、恢复清单、备用件

**按顺序做：**
1. 把实物接线/引脚/电源额定值和装配照片写入交付说明，不仅放设计图。
2. 标注运行与下载的开关/接口，准备物理断电方式和安全摆放。
3. 独立按README开机/烧录/净化一遍，与前端三轮演示。
4. 交付实物编号与软件登记device_id对应，不把COM号当永久硬件身份。

**完成判据：** 另一组员能按图恢复装配和通信；现场无需临时找线/换未测试电源。

**交接：** 组长签收实物，BA/BB记录设备映射。

**失败出口：** 备用载体/电源改变后重测基本动作，不直接沿用原测时证据。

## 4. 每次硬件联调记录

记录设备/蓝牙/电源型号、固件hash、COM/baud、接线版本、输入hex、上行hex、动作视频、供电变化、复位原因和结果。框图不能替代实测。
动作时长表只保存一个机器可读来源，由EA填写BA生成；源码步骤表变化必须使相关测时记录失效并重测。
