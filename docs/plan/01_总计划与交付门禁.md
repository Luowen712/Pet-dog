## 1. 交付承诺

用户已确定：核心闭环优先，扩展按进度纳入。本期必须交付：
- 一台真实桌宠，七基础动作码0x30～0x36、七预设表情和动作表情联动。
- 网页登录、设备认领、本人控制、受理/完成/未知结果展示、实时状态。
- 最小账号归属安全：owner过滤、改密/登出撤权、解绑/注销与交接门禁、无默认口令。
- 单进程设备链路、命令幂等、不自动重放、故障可诊断可恢复。
- 源码、配置样例、迁移/备份恢复、烧写说明、实物接线与真实验收记录。

原功能表核心15项加F-2-06表情演示入口，共16项原编号；安全与恢复为新增S需求。天气/音乐/语音/场景/承诺提醒不强制加入；已有页面保留，正式菜单按能力隐藏，不删除成果。

## 2. 对评审意见的独立结论

DeepSeek指出的裁决、锁序、工时和迁移确实是高风险点，但阅读这四节不等于执行闭环。施工时“文件归属、接口样例、测试”不能跳过，否则每个人仍不知道交给谁、交什么。

V3已有方向保留，但本轮修订：
1. 不再让组员面对旧契约和V3两个口径；06明确最小跨组合同，J00只负责转成机器schema和向量。
2. 明确各个人的任务卡、依赖、失败出口、接收人；不只给一张周计划。
3. 保留现有票据、对账和六态结构；不重建前端、不换命名、不搬后端模型。
4. 保留现有表情POST和参数错误200信封；取消V3无必要的PUT/422迁移。
5. 对“未知命令”“255序号”“CLI交接”“新库/旧库”“提交失败”提供具体恢复测试，不用原则代替路径。
6. 工时从318h重新按任务卡分解为350h基础预算；这是估计，不是经团队承诺的可行性证明。

## 4. 架构和数据路径

Vue→HTTP路由→命令服务（鉴权/幂等/落库）→SendGate（撤销与写入协调）→DeviceSession→STM32。
固件回包→Session状态机→数据库commit→command事件；遥测→归属/会话快照→state事件。
数据库与物理write无法同一事务，不承诺恰好执行一次；采用同键不重复发送、写后不确定停止控制、人工恢复证据。
同设备仅一条运动在途，busy拒绝新运动。发送锁覆盖动作和表情等所有用户设备I/O；改密/解绑/注销提交与write用同一协调入口。具体规则只在06维护。

## 8. 迁移发布分工

BB准备只读清点、目标schema和隔离库演练；BA保证停止所有writer及启动版本检查；FE支持新旧发布窗口的登录状态清理；组长安排维护窗口。
正式发布前七步，顺序不可交换（CLI 类步骤必须在停机窗口内做完，见 06§7：会改授权或设备状态的 CLI 一律要求主机排他锁，而后端运行时拿不到该锁）：

1. 备份恢复到隔离库并验证可用（不上生产）。
2. 全部 writer 停机（后端、串口采集、清理任务全部退出）。
3. 迁移：0001 基线 → 0002 新增 → 0003 回填归档 → 0004 验数 → 0005 约束。
4. 停机窗口内用 CLI 完成全部改授权与设备状态的步骤：初始化/恢复管理员、register-device、issue-claim-code、recover-device、complete-handover。此时后端仍未启动。
5. 启动新后端（单 worker、无 reload），确认迁移版本与会话门禁通过。
6. 两账号隔离检查（HTTP 层，只读）。
7. 构建正式前端 dist（关闭 Mock）→ 开放控制。

本机监听不得绑 127.0.0.1：范围声明要求网页在手机浏览器与局域网内可用，见本节末的范围条款。
任一步失败保留现场并停新write；回退对应数据库备份和软件配置，不盲目downgrade，不丢掉发布后日志。归档不明历史的数据哈希与源行删除必须同批验证。具体顺序见BB任务卡和06§10。
正式DB操作、密码轮换、硬件复位由负责人在维护窗口执行；本轮只处理文档。

范围声明与本期计划的差异（必须回改本文件，不靠口头解释）：1.2 节原写"不做多用户权限体系，只有一个管理员角色"——本期保留单一角色，但新增账号归属隔离（owner_id + 一账号一设备），因此该句应改为"不做角色分级，但做账号归属隔离"。原写"网页在手机浏览器里能正常用"——本期保留该承诺，所以监听地址为 0.0.0.0 并要求同域部署，见上。修改方式按 1.3 节"先回到这份文档改范围，再改排期"，不新增平行文档。
